# Features

Everything Runrail Desktop does, area by area. The [README](../README.md) has the short version,
and the experimental features are listed there.

| Area | Features |
| --- | --- |
| First run | A splash with the app's icon while it loads, then setup: turn on the coding tools you use (each runs with the login it already has), choose whether Runrail reads your Claude Code and Codex plan limits (it never does unasked, and Settings can turn it off), set how much agents do on their own, and bring MCP servers and instructions over from your other tools. Settings, General runs it again. Before any project is added, the welcome screen offers Open a folder, New app, and Quick chat's shortcut, and each tool's state. |
| Threads | Projects and threads in the sidebar with live status, search, rename, keyboard switching. Pinned threads, from any project, sit in one list above the projects. Archiving says so, with Undo; the Archived row at the sidebar's foot lists archived threads by project to search, open, restore, or delete forever (after you confirm). A git bar over the composer names the repository and the branch from a new thread's first moment, then fills in the checkout's changes, the pull request with its checks, and one push or pull button. History is restored from the engine after a restart. |
| Composer | One toolbar: a `+` menu that searches files, skills, subagents, and MCP servers and turns on working toward a goal; one permissions menu with Plan, Ask, Auto-edit, and Full access (Shift-Tab switches); the model chip with its reasoning effort on a slider; a context card with the Codex or Claude Code plan's usage, once you allow Runrail to read it; dictation beside send, and talk mode in the send button's place when there is nothing to send. Claude Code, Codex, GitHub Copilot, and Pi models are listed beside connected models and run through the installed tool with its own login. Image attachments, queued prompts, steer, and stop. |
| Timeline | Streaming markdown with syntax highlighting, typed tool rows (commands, edits, reads, searches), collapsible reasoning, plans, subagent reports, approval cards that show the command or path. Consecutive tool calls fold into one line that says what they did ("Ran 4 commands, edited 2 files +19 -1") with how tests, builds, lint, type checks, and commits ended, and opens to each call; pushes, pull requests, subagents, and failures you need to act on keep their own rows, and a finished turn folds into "Worked for". |
| Review | File list with unified or split diffs, stage, unstage, and discard per file, commit box, inline comments sent back to the agent. |
| Reviews | Every open pull request on GitHub that waits on your review, that you opened, or that waits on your teams, across repositories, read through your own `gh` sign-in. Search or paste a link; each one shows its description, merge status, checks, reviews, the thread that opened it, and its changes file by file. Post a review's findings as comments, or merge, each after you confirm it; a merge goes through only if the pull request's head is still the commit you reviewed. |
| New apps | Create project, New app: name the app, pick a starter (Nifra, the default and marked Recommended, by the authors of Runrail; Vite + React; Next.js; or an empty folder), then choose where in the system's dialog. The engine runs the starter's creator at a fixed version, installs the packages, makes the first commit, and the app opens as a project. |
| Nifra | In a Nifra project, threads on Runrail's own agent get the `nifra mcp` tools and Pi threads get Nifra's instructions and tools; the thread header shows a Nifra label that says so. One switch in Settings, General turns it off ([Nifra in Runrail](../README.md#nifra-in-runrail)). |
| Worktrees | Optional worktree per thread, so parallel threads never share a checkout. Apply a worktree's changes to the main checkout in one step. |
| Best of N | Run one task on several models or coding tools (any connected model, Claude Code, Codex, GitHub Copilot, Pi) in parallel worktrees, compare diffs and check results side by side, keep the winner. |
| Import | Continue a Claude Code, Codex, or Pi session recorded for the project. The conversation becomes model context for the next prompt; the original file is untouched. Bring over skills, MCP servers, subagents, and instructions from Claude Code, Claude Desktop, Codex, Cursor, Gemini CLI, opencode, and Pi; secret values are never copied. |
| Voice | Dictation (`mod+shift+m`) from any microphone, with Apple's recognizer (optionally kept on the Mac) or Whisper running locally with a model downloaded in Settings; words to recognize; answers read aloud with the system's voices; and talk mode: speak, it sends when you pause, hear the answer, speak again. |
| Notifications | macOS notifications when a thread finishes, fails, or needs approval, or a workflow, setup, or eval run waits for you or ends (in the background or always); a click opens the thread or run; notes in the window and sounds, each chosen per event. |
| Side panel | Tabs per thread, opened and closed like a browser's (drag to reorder, `mod+t`, `mod+w`, `ctrl+tab`): terminals on a real PTY, browser previews of any http or https page (isolated from the app, no stored cookies) that the agent can open, read, and click when you turn it on per thread (pages on this computer only unless you allow any site; its scripts ask first), Review, Files (with line numbers; a file named in an answer, a tool call, or the review opens here at the line it names (Settings can send answers' files to your editor instead), and its right-click menu has your editors, Finder, and its path), and Tasks: the subagents and commands an agent left running, with live output, ports that open in a preview, and Stop. A bar over the composer keeps Stop for work that outlives its turn, and the title bar shows how many other threads are still running. |
| Workflows | Steps per project (agent turns, setups, checks, your approval, a draft pull request, a note) run by hand, on a schedule with a next-run preview, or when a pull request is opened or your review is requested. Scheduled prompts from earlier versions live here too. |
| Menu bar | Closing the window while something is pending (a turn running or queued, a workflow, setup, or eval run, a workflow that starts by itself, memory sources to sync) keeps Runrail going in the menu bar: the window and Dock icon hide, and a menu bar item says what runs, what waits, and what starts next, with Open and Quit. Hidden with nothing pending for a minute, it quits by itself. "Start in the menu bar at login" (the installed app) opens it at login with no window, under the same rule. Opening Runrail again (Finder, Spotlight) brings the window back, which matters when a full menu bar keeps the item behind the notch. After Quit, nothing runs unless "Run schedules after Quit" is on (installed app only): a small helper then opens Runrail when a schedule or trigger is due. Nothing runs while the Mac sleeps; a missed schedule runs once on wake or reopen. |
| Extensions | Plugin and package browser with verification and rollback. |
| Sharing | Developer mode only: makes a content-free share record in the engine. Nothing carries it to anyone yet; there is no Runrail Host transport in the app. |
| Updates | Release builds check the latest GitHub release at launch and every six hours, verify its signature against the key built into the app, and install only when you click Install and restart ([RELEASE.md](RELEASE.md)). |
| Look | Neutral black theme (no tinted grays), with light and "follow system" on the same tokens. Monochrome accent by default, or blue, violet, or orange; color is kept for status, so running, waiting, failed, and done read at a glance, always with an icon and a label too. Translucent sidebar on macOS. Code, diffs, and the terminal use palettes on the same ramp and follow the theme without reopening. The first three text tiers pass WCAG AA on every surface, and a test holds every stylesheet to the tokens. |
| Everywhere | A rail of icons down the left edge, each named in a pill on hover or focus, with a key per place (`mod+1` Threads, `mod+2` Reviews, `mod+3` Agents, `mod+4` Workflows, `mod+5` Evals, `mod+6` Integrations, `mod+7` Memory, `mod+8` Office). Command palette (`mod+k`), full keymap (`mod+/`), compact density, responsive layout. Every control shows its loading, failed, disconnected, and approval states. |

Features the connected engine does not advertise are shown as unavailable with
the reason, never faked.
